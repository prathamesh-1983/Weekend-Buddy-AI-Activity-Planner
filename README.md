Weekend Buddy: An AI Agent That Makes Free Time Easier to Enjoy

What and who : Free time should feel refreshing, not like another decision to make. But when a weekend arrives, it can be surprisingly difficult to choose something enjoyable that fits your budget, available time, energy level, and whether you want to be alone or with other people. That is why I built **Weekend Buddy**, a dark-themed AI activity-planning prototype that helps people turn a few preferences into a realistic mini-itinerary. It is designed for students, young professionals, families, and anyone who wants to spend less time deciding what to do and more time enjoying offline activities. Instead of returning a generic list, Weekend Buddy takes practical constraints into account. A user can choose a budget, how much free time they have, whether they prefer indoor or outdoor activities, their energy level, who is joining, and how many activities they want in the plan. The app then suggests options such as a nature walk, journaling, sketching, reading, cooking, a board-game session, or a casual sport.The goal is not to plan a perfect weekend for everyone. It is to make the first useful decision easier—and let people adjust the plan when their mood changes.

How I built it : I built Weekend Buddy as a Python application with a Streamlit interface. Streamlit made it possible to create an interactive web experience quickly while keeping the project understandable and easy to run locally.
The project is organised into a few small parts:

- `app.py` contains the user interface, preference controls, activity cards, progress checklist, and plan-adjustment interactions.
- `data/activities.json` stores the starter activity catalogue, including each activity’s category, estimated cost, duration, energy level, social preference, and description.
- `agent/tools.py` contains the planning tools. One filters activities against hard constraints; the other assembles a feasible itinerary without exceeding the selected time or budget.
- `agent/planner.py` connects those tools, calculates totals, and returns a short explanation. It also recognises a small set of natural-language adjustments.
- `tests/test_planner.py` checks important behaviours such as budget and time limits.

The agent workflow is deliberately straightforward. First, the app converts the user's choices into structured preferences. Next, the filtering tool removes activities that do not fit those constraints. The itinerary builder selects from the remaining options and calculates the estimated spend and total duration. Finally, the app presents the plan and explains why it fits. I also added **optional Amazon Bedrock integration** using the AWS SDK for Python (`boto3`). When a model ID and valid AWS credentials are configured, Bedrock can generate a concise, personalised explanation of the selected activities. The core planner does not depend on Bedrock, so the prototype can still be run locally without an AWS model configured. This fallback is useful during development and makes it easier to test the interface and constraint logic independently of model access. To run the project locally, install the dependencies with `python -m pip install -r requirements.txt`, then start the app with `streamlit run app.py`. The README contains the setup instructions and optional Bedrock configuration. AWS credentials should be configured using an approved local method and must never be committed to the repository.

The delightful detail : The detail I focused on is **making changes feel effortless**. A user does not need to start over when they change their mind. They can type a simple adjustment such as “make it cheaper,” “I want something indoors,” “make it shorter,” or “I need something relaxing.” Weekend Buddy recognises the supported preference and rebuilds the itinerary. That small interaction matters because plans often change in real life. Maybe it starts raining, the user has less time than expected, or they decide to stay home. A helpful agent should make those changes easy rather than forcing the user through the entire setup again. I paired that interaction with a dark interface using purple and indigo accents, activity cards, time and cost estimates, a remaining-budget summary, and a checklist for completed activities. The visual design aims to feel calm and approachable, while keeping the practical information easy to scan. I tested the planner logic with automated tests covering budget and time filtering, itinerary constraints, preference adjustments, and summary output. These tests help verify the rules the app controls directly. They do not prove that every generated recommendation is perfect, so the app labels costs as estimates and does not claim to verify local venue hours, availability, or bookings.

For a useful demonstration, enter a budget and a time limit, generate a plan, and then request a change such as “make it cheaper and indoors.” Show the updated activities and the recalculated totals. This demonstrates both the user experience and the constraint-based planning behaviour. Weekend Buddy is a prototype, and there is more I would like to improve: richer activity data, more robust conversational understanding, better variety across repeated plans, and optional location-aware suggestions based on verified sources. I would also like to gather feedback from people using it to discover which recommendations feel genuinely useful. My main takeaway from building Weekend Buddy is that an agent does not need to be complicated to be helpful. A clear problem, a few reliable tools, honest constraints, and a thoughtful interaction can make a small AI experience feel much more useful.
